- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** - Determinism
  - ML systems: more deterministic. A model takes input and immediately gives a single prediction; behavior and evaluation are straightforward to reason about.
  - LLM apps: less deterministic. Outputs depend on the prompt, retrieved context, and other runtime factors, so results can change with inputs and context.

- Dynamic cost
  - ML systems: cost/compute is relatively stable and predictable for a given batch (example given: 100 rows -> x units).
  - LLM apps: cost and compute are dynamic — they change with the input, the output length, retrieved context, and the application’s workflow steps.

- Input–output tracking
  - ML systems: you generally do not track an entire input-to-output journey for each prediction because there is no multi-step workflow; evaluation is just comparing ŷ to y using clear formulas (accuracy, precision, recall, F1).
  - LLM apps: there is a workflow that can vary in length and complexity; you must track that workflow and use application-specific metrics (e.g., RAD-based, chat summarizer, agentic metrics), because metrics and tracking needs change with the application.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>
